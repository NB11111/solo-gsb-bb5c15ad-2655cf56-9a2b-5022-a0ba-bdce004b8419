# 木工短料下料优化

供木工工作室使用的短料下料网页。输入**新料（可购买的原料）长度**、**锯缝宽度**、各规格的**长度和数量**，
并可选录入**余料库存**（多种余料长度及各自可用根数），系统先把同规格裁片展开成单片（总裁片数上限 12 片），
再通过精确搜索求出具优方案，并显示每根料（余料/新料逐根标明）的裁片顺序（同根内按长度从大到小，即建议裁切顺序）与余长，
同时汇总各规格余料的消耗与剩余根数，结果可在浏览器中直接打印。

## 计算规则

- 同规格按数量展开成独立裁片参与计算（编号 A1、A2…，B1、B2…）；相同长度的多行视为同一规格。
- **余料库存可选**：录入多种余料长度及各自可用根数，计算时每根余料**最多使用一次**；
  原料长度仍表示可购买的新料，新料根数不限。未录入余料时按全部使用新料计算，结果与原逻辑一致。
- 优化目标（在所有可行方案中按以下顺序比较，深度优先精确搜索 + 剪枝，保证全局最优）：
  1. **新料根数最少**；
  2. 新料根数相同时，**投入原料总长度最小**（优先用更短的余料，避免无谓占用长料）。
- **只有同一根料上相邻的两片之间才计一条锯缝**：
  一根料放 k 片时，占用长度 = 各片长度之和 + (k − 1) × 锯缝宽度；单片独占一根时不计锯缝。
- 每根料标明是**余料**还是**新料**及其长度，并显示：裁片顺序、片数、锯缝条数、已用长度、余长；
  另给出新料/余料根数、投入原料总长度、锯缝总数、总余长与综合利用率，
  以及各规格余料的**库存根数、消耗根数、剩余根数**汇总。
- 输入校验（错误时返回明确原因）：
  - 新料长度必须大于 0，锯缝宽度必须不小于 0，长度均为正数、数量为正整数；
  - 至少填写一条裁片规格且总片数 ≥ 1；
  - 总裁片数不得超过 12 片；
  - 单片长度超过新料长度时，提示“单片无法放入原料”并指出是哪一条规格；
  - 余料行长度/根数留空视为未填写（不参与计算）；相同长度的余料多行自动合并根数；
    余料单种根数上限 99、规格种类上限 50 种。

长度单位保持一致即可（如全部用毫米）。

## 技术栈

Node.js + Express（后端计算 API 与静态页面托管）+ 原生 JavaScript / HTML / CSS（前端，无构建步骤）。

## 单条启动命令（Docker Compose）

```bash
docker compose up --build
```

依赖会在**容器启动时自动安装**（首次启动执行 `npm install --omit=dev`，
`node_modules` 由 Docker 命名卷持久化，后续启动自动跳过安装）。

启动后在浏览器访问：

```
http://localhost:3000
```

## 必要配置

| 配置项 | 方式 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 网页访问端口 | Compose 端口映射 `${PORT:-3000}:3000` | `3000` | 宿主机端口可用环境变量 `PORT` 修改 |
| 容器监听端口 | 容器内环境变量 `PORT` | `3000` | 通常无需修改 |

如需改用 8080 端口访问：

```bash
PORT=8080 docker compose up --build
```

然后访问 http://localhost:8080 。

后台运行与停止：

```bash
docker compose up --build -d   # 后台启动
docker compose down            # 停止并删除容器
docker compose logs -f         # 查看日志
```

## 不用 Docker 的本地运行方式

需要 Node.js 18 及以上。

```bash
npm install
npm start
```

然后访问 http://localhost:3000 。

## 打印方案

计算出方案后点击结果区右上角的 **“打印方案”** 按钮（或浏览器 Ctrl/⌘ + P），
打印样式会自动隐藏输入区与按钮，只输出方案标题、汇总信息、余料库存消耗表和每根料的裁片示意与顺序。

## 访问地址与端口

默认通过 Docker Compose 启动后，在浏览器访问：

```
http://localhost:3000
```

- 容器内监听端口固定为 **3000**；
- 宿主机访问端口默认 **3000**，可用环境变量 `PORT` 修改，例如 `PORT=8080 docker compose up --build` 后访问 http://localhost:8080 。

## API 说明

`POST /api/optimize`

请求体：

```json
{
  "stockLength": 2440,
  "kerf": 3,
  "items": [
    { "length": 800, "qty": 2 },
    { "length": 600, "qty": 2 },
    { "length": 400, "qty": 1 }
  ],
  "leftovers": [
    { "length": 1200, "qty": 2 },
    { "length": 900, "qty": 1 }
  ]
}
```

- `leftovers` 可选：余料库存，元素为 `{ length, qty }`（长度 + 可用根数）；
  缺省或行内长度/根数为空串时视为不参与计算；相同长度自动合并根数。
- 返回结果中：
  - 每根料 `bins[]` 带 `kind`（`"leftover"` 余料 / `"new"` 新料）、`source`（“余料”/“新料”）与该根实际长度 `stockLength`；
  - 汇总含 `newBinCount`、`leftoverBinCount`、`totalStockLength`（投入原料总长度）；
  - `leftoverSummary[]` 按余料规格给出 `length / available / used / remaining`（长度/库存/消耗/剩余根数）；
  - `hasLeftovers` 表示本次是否录入了余料；未录入时各字段保持与纯新料方案一致的含义。

输入非法或单片无法放入原料时返回 HTTP 400 与 `{ "ok": false, "error": "明确原因" }`。
